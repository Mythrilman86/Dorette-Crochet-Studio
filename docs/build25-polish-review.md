## Nine changes

1. Recycle Bin uses the same 54-pixel layered-art thumbnail renderer as Projects. Rendering is deferred with IntersectionObserver; removed canvases are unobserved. No source mutation.
2. Opening New Project details focuses and selects the name. It does not touch ordinary project renaming or subsequent deliberate caret editing.
3. Creator buttons have mouse hover, distinct pressed state, focus-visible outlines, touch-action and accessible disabled states. Pressed state overrides hover correctly.
4. Floating Back to Top appears after meaningful scrolling; hides near top, over dialogs and when a touch text editor/keyboard would conflict. Uses safe-area placement, keyboard focus and reduced-motion preferences.
5. Oversized PNG/JPEG input is optimized locally in a worker. Up to 40 MiB / 80 MP input is accepted for processing; output is bounded by the existing 5 MiB / 16 MP master limits. Resize requests target <=4096-pixel longest side and <=12 MP, retain aspect ratio, PNG transparency and progressive quality/size reduction. Inputs beyond safe limits or unsupported worker decoding fail clearly. No cloud upload. Gallery/Downloads files remain unchanged. Optimized bytes become the explicitly labeled authoring master, with bounded provenance, dimensions, size and checksum. Older imported images are not rewritten. Backups carry those exact masters and snapshots retain their original referenced versions. Decoding may still have implementation-specific memory overhead; maximum-size Samsung photos require device testing.
6. Studio navigation has separate labeled, bordered links/icons and spacing for following Written Patterns versus authoring in Pattern Creator.
7. Sticky snapshot title bar includes an accessible top-right X, retains the bottom Close button, Back/Escape behavior and restores opener focus. Snapshots remain read only.
8. Relative save age derives from the last committed updatedAt. It remains visible during unsaved/failed work, updates while open/focused and persists through existing draft storage. Future timestamps and detected session clock shifts show an explicit clock-change message rather than negative/false elapsed times. Historical clock changes across restart cannot be reconstructed; exact time is available in the tooltip.
9. Missing-draft backup errors appear beside the backup controls. Corrupt backups clear pending import state, keep confirmation disabled and open a plain-language dialog with fixed safe details, dismissal and Back support. Save failures have a serious recovery dialog. Other actions can show local contextual messages rather than relying only on the save banner. Private content is not recorded in diagnostics.

## Independent review: current-source verification and disposition

A. CONFIRMED: accepted/current worker catches resource failure and calls caches.delete(CACHE). The independent Chromium experiment reproduces live-cache deletion when a modified worker deliberately reuses the active name. A distinct candidate name preserves the old cache. Build 25 adds a deterministic content-derived cache identity covering the worker logic, every precached file, app version and Android build. Both web/mobile builds reject a stale identity. The checked-in worker gets an explicit Build 25 identity; root Pages source and generated builds agree. This prevents the confirmed collision through the verified release pipeline. It is not a claim that arbitrary hand-edited workers are runtime-safe. The cleanup implementation itself is not rewritten in this candidate.

RUNTIME PROPOSAL, NOT IMPLEMENTED: a guard must establish cache ownership before any candidate writes or cleanup. An existence-only guard is insufficient: the worker-stop experiment leaves a legitimate partial cache which must be retryable. A robust guard needs an active-worker cache-identity handshake plus conservative treatment of legacy/unresponsive workers and an explicitly tested abandoned-candidate recovery path. This has migration/retry risk and needs a separate reviewed patch/approval before implementation. Do not deploy a speculative staging/lazy-cache rewrite. Public website release review must explicitly resolve/accept this remaining runtime limitation; Android authoring need not wait for Issue #24.

B. PARTIALLY REPRODUCED UNDER CONTROLLED FAULT: Chrome 157.0.8103.38 (headless Windows) HTTP503 failures yielded resource-specific errors and cleanup. Deliberate ServiceWorker.stopWorker during install yielded redundant/stopped lifecycle events, "Operation has failed (unknown reason)", 2 of 3 synthetic cached resources, retained the old active cache, and successful full retry. The update() promise itself had already resolved; lifecycle events captured the failed install. This supports a lifecycle-termination hypothesis, not the cause of spontaneous Issue #24. No real-origin/profile data or project databases are used. The raw local trace contains synthetic lifecycle statuses and scrubbed test-origin errors; the product diagnostics schema is not widened to arbitrary strings. No claim of 17 independent ordinary trials or a solved cause is made.

C. CONFIRMED: readStandaloneSettings defaulted phoneControls to false while runtime defaults expanded. Corrected to true for unset only; explicit true/false remain intact. Category label now says all layouts. Round-trip tests cover each state and old backup imports remain compatible.

D. CONFIRMED: personalized mode used an inclusion whitelist, which hides future unknown sections. Migrate known old exclusions to an explicit hiddenSections list, preserving intentionally hidden known sections and showing new sections. Known/order keys provide migration context. Backup sanitizer carries the new optional fields and still accepts old files. Reordering merges the latest saved preferences rather than overwriting personalization from stale startup state. Find-a-Tool temporary reveal classes are removed on Escape/outside interaction while interaction inside the revealed section stays usable; no preference mutation is needed for a reveal.

## Limits and remaining authoring scope

Image optimization is import-only. Unmodified input bytes remain unchanged; optimized masters are not mislabeled as original photos. Worker timeout and input/pixel bounds prevent unbounded accepted work, but are not a physical memory/battery benchmark. HEIC and >80MP/>40MiB inputs are rejected with a Gallery-copy instruction. Original masters can retain metadata if not re-encoded; future buyer-facing export must strip private metadata. Existing .deepattern v1 retains compatibility via optional optimization provenance; hashes always cover actual stored bytes. Chart ZIP, Settings JSON and .deewritten meanings/schemas remain separate.

No Stage B/C PDF/listing implementation, new paid library/service, account, subscription, advertisement or deployment is included. Published v2.6.0 and accepted Build 24 are preserved. Keep PR #26 draft, publish only source/CI as authorized, and distribute the verified APK privately for Samsung testing.
